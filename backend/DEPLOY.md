# FeatherPanel 后端与部署

无需 Docker 的原生快速安装：在完整发布包根目录运行 `sudo bash install.sh`，默认监听 80，并配置 systemd 开机启动。用 `sudo featherpanel key` 查看初始化密钥。详见 [原生部署](../docs/native-deployment.md)。

前端版式保留。Node.js 24 后端使用 SQLite 保存房间与任务，Python 3 负责存档压缩和安全校验。无 npm 第三方依赖。Linux 容器内用 screen 管理 DST 世界进程，不需要连接独立 DMP 面板。

## 当前可用代码

- 登录与管理员鉴权，同源接口、文件访问范围限制。
- 房间配置持久化，生成 cluster.ini、每层 server.ini、leveldataoverride.lua、modoverrides.lua；隐藏端口跨房间分配，密码与游戏令牌不写入前端本地草稿。
- 通过 SteamCMD 安装/更新游戏、按 32/64 位启动世界、关闭、重启、回档、重置；长操作保存为可查询任务。
- 读取服务器/聊天日志和面板操作记录，读取实际 screen 会话状态。
- 通过固定只读游戏控制台查询采集各世界玩家、天数、季节、时段；采集失败显示不可用，不伪造零人。CPU 百分比使用主机计数器差分采样。
- 地图从最近存档读取地形、道路和实体位置，运行时使用已安装游戏的 KTEX 纹理与原版地图图标绘制 PNG；支持森林、洞穴、缩放、拖动及下载。原版素材不随面板分发。地图采集缓存 60 秒，渲染按内容缓存两张图并单并发执行；状态缓存 4 秒。
- 整房备份、每日定时备份、上传 ZIP/TAR.GZ/TGZ 校验并入库，保留活动世界；快照按世界列出，恢复前整房备份，要求所有世界存在同一天的快照。
- 模组 ID 查询、推荐列表、名称搜索、SteamCMD 下载/更新、共享模组安装列表、安全静态配置解析、删除接口。启用组合由保存房间配置写入。
- backend-client.js 在后端提供 HTML 时自动加载，把现有前端接入这些接口；双击 index.html 仍为本地预览。

## 已有服务的云服部署

在独立目录（例如 /opt/feather-panel）解压交付包。先运行只读检查：

```sh
sh backend/scripts/preflight.sh
```

确认剩余资源足够，内网 TCP 80 和游戏 UDP 直连端口没有冲突，已有服务的部署信息已保留。不要执行全机容器清理或停机命令。下面的 Compose 项目名固定为 featherpanel，与其他项目隔离。

```sh
cp .env.example .env
# 编辑 .env，填写 FEATHER_PUBLIC_HOST 为游戏服务器公网 IP。
docker compose -p featherpanel build
docker compose -p featherpanel up -d
docker compose -p featherpanel exec feather cat /data/admin-token
```

最后一条命令显示管理员密钥，只保存在自己的终端/密码管理器中。面板默认直接监听云服 `0.0.0.0:80`，不要求 Nginx、SSH 隧道或额外反向代理。使用 NAT 云服时，让云厂商把公网端口映射到内网 TCP 80；面板外网访问地址由云厂商提供。部署前必须确认内网 80 没有被其他服务占用。更换游戏端口时，只需在房间设置填写森林/洞穴直连 UDP 端口，并确保云厂商已转发选用的 UDP 端口；内部 SHARD、Steam 查询和认证端口由面板按 DMP 默认范围自动分配。3 GB/2 核为容器限制示例，需根据现有服务与游戏负载调整。

发行版默认使用 Docker 命名数据卷。更新已有部署时，保留原 Compose 的数据卷或绑定目录；例如原本使用 `./data:/data` 的实例必须继续使用该绑定，避免切换到空卷。

房间设置只显示每层世界的直连端口。内部 SHARD、Steam 查询和认证端口沿用 DMP 默认范围，分别从 21001、31001、41001 开始自动避让分配；保存设置会保留现有内部端口。导入存档时读取原存档的有效内部端口配置，不新增用户填写项。

## 安装游戏和首次开服

登录后先保存房间配置。游戏安装入口为鉴权接口 POST /api/game/install，可在登录面板的浏览器开发者工具中执行：

```js
const {data}=await fetch('/api/game/install',{method:'POST'}).then(r=>r.json());
console.log('安装任务', data.taskID);
// 用返回 ID 查询状态，state=succeeded 才安装完成。
await fetch('/api/tasks/'+data.taskID).then(r=>r.json());
```

也可在容器终端直接使用后端鉴权调用：

```sh
docker compose -p featherpanel exec feather node --input-type=module -e '
import fs from "node:fs";
const token=fs.readFileSync("/data/admin-token","utf8").trim();
const result=await fetch("http://127.0.0.1:80/api/game/install",{method:"POST",headers:{Authorization:"Bearer "+token}}).then(r=>r.json());
console.log(result);'
```

安装可能需要数分钟与数 GB 磁盘。保存配置、下载启用的模组后点击“启动游戏”；世界会话存在代表进程运行，是否加入大厅需检查游戏日志与实际联机。第一次安装、默认令牌、32/64 位二进制依赖和创意工坊访问必须在真实 Linux 云服验证。默认令牌来自许可复用的 DMP 源码，可能失效；可通过 FEATHER_CLUSTER_TOKEN 替换，不新增前端输入。

```sh
cd backend
FEATHER_PYTHON=python3 npm test
```

本地测试使用临时目录与模拟进程状态，真实校验 SQLite、HTTP 登录、配置生成、存档 ZIP/TGZ、路径安全、备份恢复和任务状态。测试结束关闭临时 HTTP 服务，不启动前端开发服务器。Windows 可以测试后端文件和接口，真实游戏控制要求 Linux。

地图使用已安装游戏的原版贴图和地图图标，以高分辨率 PNG 返回；素材缺失时显示错误，未识别地形在页面提示。服务端按存档内容缓存图片，浏览器缓存 60 秒。地图基于最近存档，世界关闭时仍可读取；首次绘制可能需要数秒，支持 Pillow 的 Python 3 是必需依赖（Docker 已安装 python3-pil）。“检查游戏”查询科雷公共服务器列表，按房间名、玩家上限、主世界端口及 FEATHER_PUBLIC_HOST 匹配；未配置公网地址时只能按名称、容量和端口匹配。模组配置支持常见的语言判断、字符串拼接、生成选项循环及辅助函数，通过有计算限制的数据解释器处理；不提供 Lua 系统、文件或网络能力，不支持的结构会显示原因。当前快照以 .meta 中 cycles 判断同一天；缺少天数或多世界不齐时拒绝恢复。恢复失败会保留恢复前备份。上传当前仅加入备份库，没有直接覆盖活动房间的导入按钮。个人预设仍保存在当前浏览器。

# Docker 部署后的账号登录

容器第一次启动会在持久化数据卷创建一次性初始化密钥。读取密钥：

```bash
docker compose exec feather cat /data/setup-key
```

打开面板登录页，展开“首次部署？创建管理员账号”，填写初始化密钥、管理员用户名和至少 10 位密码。创建成功后，`/data/setup-key` 会被删除；账号密码哈希、账号状态和会话保存在 `/data/panel.sqlite`，以后重建容器不会丢失。

默认关闭公开注册。若确实需要让用户自行注册，在 `.env` 设置 `FEATHER_ALLOW_REGISTRATION=1` 并重建容器；首次部署仍必须先用初始化密钥创建管理员。原有管理员密钥登录保留，用于旧脚本和升级维护。
